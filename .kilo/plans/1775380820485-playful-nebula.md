# Employee Import Feature — Implementation Plan

## Overview

Build a fully functional bulk employee import feature into the existing admin employees page (`/employees`). The UI dialog already exists as a stub — it needs the backend endpoint, file parsing, validation, and frontend wiring.

**Key Design Decisions:**
- **Full employee data** import (all fields from the Employee model)
- **zkid left null** during import — assigned later when fingerprint registration occurs (same deferred pattern as the current manual flow, but without device sync at creation time)
- **Partial import** strategy — valid rows are committed, invalid rows are skipped and reported

---

| Component | Status |

| Device sync | `addUserToDevice()` in zkServices.ts — requires zkid |
| Fingerprint enrollment | `POST /api/employees/:id/enroll-fingerprint` — triggers device-side enrollment |

---

## Architecture

```
User uploads .xlsx/.csv
       │
       ▼
Frontend parses file (xlsx library)
       │
       ▼
Frontend sends JSON array → POST /api/employees/import
       │
       ▼
Backend validates each row
       │
       ├── Valid rows → createEmployee() (modified: no zkid, no device sync, no email)
       │
       └── Invalid rows → collect errors
       │
       ▼
Response: { success, imported: [...], errors: [...] }
       │
       ▼
Frontend shows results summary + error detail table
```

### 1.2 New Controller

Add `importEmployees` controller function:

```ts
export const importEmployees = async (req: Request, res: Response) => {
  // Accept: { employees: Array<ImportEmployeePayload> }
  // For each row:
  //   1. Validate required fields (firstName, lastName, email)
  //   2. Check duplicates (email, employeeNumber)
  //   3. Create employee with zkId: null (deferred assignment)
  //   4. Skip device sync and welcome email (done later via fingerprint enrollment)
  // Return: { success, imported: [...], errors: [{ row, data, errors: [...] }] }
}
```

**Key behavioral differences from `createEmployee`:**
- **No zkid assignment** — `zkId` stays `null` in the DB
- **No device sync** — skip `addUserToDevice()` call
- **No welcome email** — credentials sent later after fingerprint enrollment
- **No registration mutex needed** — since we're not assigning zkid, there's no race condition on `findNextSafeZkId()`
- **Batch processing** — loop through array, collect successes and failures per-row

```tsx
const handleImport = async () => {
  if (!importFile) return
  setIsImporting(true)

  try {
    // 1. Parse file client-side
    const data = await importFile.arrayBuffer()
    const workbook = XLSX.read(data)
    const worksheet = workbook.Sheets[workbook.SheetNames[0]]
    const rows = XLSX.utils.sheet_to_json(worksheet, { defval: '' })

    // 2. Map columns to API payload
    const employees = rows.map((row: any) => ({
      firstName: row['First Name'] || row['FirstName'] || row['firstName'] || '',
      lastName: row['Last Name'] || row['LastName'] || row['lastName'] || '',
      middleName: row['Middle Name'] || row['MiddleName'] || row['middleName'] || null,
      suffix: row['Suffix'] || row['suffix'] || null,
      gender: row['Gender'] || row['gender'] || null,
      dateOfBirth: row['Date of Birth'] || row['DateOfBirth'] || row['dateOfBirth'] || null,
      email: row['Email'] || row['email'] || null,
      role: row['Role'] || row['role'] || 'USER',
      department: row['Department'] || row['department'] || null,
      position: row['Position'] || row['position'] || null,
      branch: row['Branch'] || row['branch'] || null,
      contactNumber: row['Contact Number'] || row['ContactNumber'] || row['contactNumber'] || null,
      employeeNumber: row['Employee Number'] || row['EmployeeNumber'] || row['employeeNumber'] || null,
      hireDate: row['Hire Date'] || row['HireDate'] || row['hireDate'] || null,
      employmentStatus: row['Employment Status'] || row['EmploymentStatus'] || row['employmentStatus'] || 'ACTIVE',
      shiftId: row['Shift ID'] || row['ShiftId'] || row['shiftId'] || null,
    }))

    // 3. Send to backend
    const res = await fetch('/api/employees/import', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      credentials: 'include',
      body: JSON.stringify({ employees }),
    })

    const result = await res.json()

    // 4. Show results
    if (result.imported?.length > 0) {
      showToast('success', 'Import Complete', `${result.imported.length} employees imported successfully`)
      if (result.errors?.length > 0) {
        showToast('warning', 'Partial Import', `${result.errors.length} rows had errors`)
      }
      // Refresh employee list
      await fetchEmployees()
    } else {
      showToast('error', 'Import Failed', result.errors?.[0]?.errors?.join(', ') || 'No valid rows found')
    }

    // 5. Close dialog and reset
    setIsImportOpen(false)
    setImportFile(null)
  } catch (error) {
    showToast('error', 'Import Failed', 'An unexpected error occurred')
  } finally {
    setIsImporting(false)
  }
}
```

## Phase 3: zkid Assignment During Fingerprint Enrollment

### How it works

1. **Import creates employees** with `zkId: null`
2. **Admin reviews** imported employees on the dashboard (they'll show "No zkId" or similar indicator)
3. **Admin triggers fingerprint enrollment** per employee (existing `enroll-fingerprint` endpoint)
4. **During fingerprint enrollment**, the system auto-assigns zkid and syncs to device

### Required Change to Fingerprint Enrollment

**File:** `backend/src/services/zkServices.ts` — `enrollEmployeeFingerprint()` (line ~1159)

Current code at line 1159-1161:
```ts
if (!employee.zkId) {
    return { success: false, message: `Employee ${employeeId} has no zkId assigned.` };
}
```

Replace with zkid auto-assignment logic:
```ts
if (!employee.zkId) {
    // Auto-assign zkid for imported employees at enrollment time
    const release = await acquireRegistrationMutex();
    try {
        const nextZkId = await findNextSafeZkId();
        await prisma.employee.update({
            where: { id: employeeId },
            data: { zkId: nextZkId, updatedAt: new Date() },
        });
        employee.zkId = nextZkId; // update local reference
        console.log(`[Enrollment] Auto-assigned zkId=${nextZkId} to employee ${employeeId} (${employee.firstName} ${employee.lastName}).`);
    } finally {
        release();
    }
}
```

**Why this works:**
- The existing `enrollEmployeeFingerprint` already connects to the device and writes the user record via `zk.setUser()` at line 1243
- By assigning zkid before that point, the employee gets created on the device as part of the normal enrollment flow
- The registration mutex prevents race conditions if two admins trigger enrollment simultaneously
- After enrollment, the employee is fully active — zkid assigned, device synced, fingerprint captured

### No Additional Endpoints Needed

The existing `POST /api/employees/:id/enroll-fingerprint` endpoint handles everything. No bulk assign endpoint is needed — admins activate employees one at a time during fingerprint enrollment.

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| Duplicate email/employeeNumber | Pre-check against existing DB records before each insert |
| Large file performance | Limit to 1000 rows; process sequentially with per-row error collection |
| zkid collision on later assignment | `findNextSafeZkId()` checks both DB and device UIDs — already handles this |
| Partial import confusion | Clear UI showing exactly which rows succeeded and which failed with reasons |
| Column name mismatch | Support multiple column name formats (with spaces, without, camelCase) |
| Date format issues | Accept ISO format (YYYY-MM-DD) in template; document in template instructions |
